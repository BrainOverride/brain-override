# 🎨 스트룹 테스트 (StroopTest)

> 글자가 **뜻하는 색**이 아니라 글자가 **칠해진 색**을 맞히는 주의력 게임

| 항목 | 내용 |
| --- | --- |
| 클래스 | `StroopTest extends MiniGame` |
| 파일 | `src/games/StroopTest.java` |
| 담당 | 심소민 |
| 두뇌 영역 | 주의 · 억제 |
| 구현 난도 | 중 (ANSI 색상, Windows 한글 출력) |

---

## 1. 규칙

1. 색 이름 글자(빨강, 초록, 노랑, 파랑)가 **다른 색으로 칠해져** 나옵니다.
2. 글자의 뜻이 아니라 **글자의 색**을 번호로 입력합니다.
   - `1` 빨강 · `2` 초록 · `3` 노랑 · `4` 파랑
3. 5문제 중 **4개 이상 맞히면 성공**입니다.

**왜 어려운가 (스트룹 효과)**: 사람은 글자를 보면 자동으로 읽어버립니다. "빨강"이라는 글자가 파란색이면, 읽은 뜻(빨강)을 억누르고 색(파랑)을 말해야 해서 반응이 느려지고 실수가 늘어납니다. 이 게임은 그 **억제 능력**을 측정합니다.

## 2. 화면 예시

```
=== 스트룹 테스트 (Normal) ===
글자의 '뜻'이 아니라 '색'을 고르세요.
1 빨강  2 초록  3 노랑  4 파랑

[1/5]   노랑        ← 실제로는 초록색으로 출력
입력: 2   ✅

[2/5]   파랑        ← 빨간색으로 출력
입력: 4   ❌ 글자를 읽었네요! (정답: 1 빨강)
```

**정답을 한글이 아니라 번호로 받는 이유**
- 한글 입력은 한/영 전환이 필요해서, 주의력이 아니라 타자 속도를 재게 됩니다.
- Windows 콘솔에서 Java `Scanner`로 한글을 입력받으면 인코딩 설정에 따라 깨질 수 있습니다. 숫자는 이 문제가 없습니다.

## 3. 난이도별 설정

| 난이도 | 의미와 색의 관계 | 특수 규칙 | 시간 보너스 기준(제안) |
| --- | --- | --- | --- |
| Easy | 일치 비율 높음 (약 60%가 일치) | 없음 | 30초 |
| Normal | 항상 불일치 | 없음 | 25초 |
| Hard | 항상 불일치 | **문제마다 "글자를 읽어라 / 색을 말해라" 지시가 무작위로 바뀜** | 30초 |

## 4. Hard: 지시 전환 규칙

```
[3/5] 지시: 📖 글자를 읽어라      파랑   ← 빨간색 출력 → 정답 4(파랑)
[4/5] 지시: 🎨 색을 말해라        초록   ← 노란색 출력 → 정답 3(노랑)
```

- 문제마다 지시를 50% 확률로 고릅니다. 같은 지시가 3번 연속 나오지 않게 합니다(연속되면 전환의 의미가 사라짐).
- **왜 규칙 변화인가**: Normal은 "항상 색"이라는 한 가지 억제만 하면 되지만, Hard는 매 문제 어떤 정보를 억눌러야 하는지부터 판단해야 합니다. 같은 화면에서 정답 기준 자체가 바뀝니다.

## 5. ANSI 색상

콘솔 글자에 색을 입히려면 글자 앞에 **ANSI 이스케이프 코드**를 붙이고, 뒤에 초기화 코드를 붙입니다.

| 색 | 코드 |
| --- | --- |
| 빨강 | `"\u001B[91m"` |
| 초록 | `"\u001B[92m"` |
| 노랑 | `"\u001B[93m"` |
| 파랑 | `"\u001B[94m"` |
| 초기화 | `"\u001B[0m"` |
| 굵게 | `"\u001B[1m"` |

- 밝은 색 코드(`91~94`)를 씁니다. 기본 색(`31~34`)은 어두운 배경에서 파랑이 거의 안 보입니다.
- 출력 뒤에 반드시 **초기화 코드**를 붙입니다. 빠뜨리면 이후 모든 출력이 그 색으로 물듭니다.
- 색 입히기는 다른 게임에서도 쓸 수 있으므로 `ConsoleUtil.color(text, colorCode)` 같은 공통 메서드로 만듭니다.
- **Day 1 오전 확인**: 셋의 컴퓨터(IntelliJ 콘솔, Windows Terminal)에서 4색이 구분되는지 먼저 봅니다. 안 되면 이 게임의 출력 방식을 바꿔야 하므로 가장 먼저 확인할 리스크입니다.

### 구현 순서

1. 난이도별 일치 비율, 지시 전환 여부를 조회합니다.
2. 색 이름 4개와 색 코드 4개를 **같은 순서**로 준비합니다. 인덱스 0~3이 번호 1~4에 대응합니다.
3. 5번 반복합니다.
   1. 글자(뜻)를 랜덤으로 고릅니다.
   2. 일치 비율에 따라 색을 고릅니다. 불일치면 글자와 다른 색 중에서 고릅니다.
   3. Hard면 이번 문제의 지시를 고릅니다(3연속 방지).
   4. 지시에 따라 정답을 정합니다: 색을 말해라 → 색, 글자를 읽어라 → 글자 뜻.
   5. 색을 입혀 출력하고 1~4 입력을 받아 채점합니다.
4. 정답 수가 4 이상이면 성공입니다.

**설계 힌트**: 색 이름과 색 코드를 짝지어 관리하려면 배열 두 개를 같은 인덱스로 쓰는 방법과, `enum`을 만드는 방법이 있습니다. `enum`을 배웠다면 `enum StroopColor { RED("빨강", "\u001B[91m"), ... }`처럼 묶어보세요. 이름과 코드가 따로 놀 수 없게 됩니다.

### 쓸 만한 Java API

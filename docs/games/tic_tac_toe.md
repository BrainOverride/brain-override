# ⭕ 삼목 대결 (TicTacToe)

> 3×3 판에서 컴퓨터와 번갈아 두며 한 줄 3개를 먼저 만드는 전략 게임 (틱택토, OX 게임)

| 항목 | 내용 |
| --- | --- |
| 클래스 | `TicTacToe extends MiniGame` + `AIStrategy` 인터페이스와 구현 3개 |
| 파일 | `src/games/tictactoe/` (6개 파일) |
| 담당 | 정종일 |
| 두뇌 영역 | 전략 |
| 구현 난도 | 중상 (Minimax 재귀) |

---

## 1. 규칙

1. 플레이어는 `O`, 컴퓨터는 `X`입니다. **플레이어가 먼저** 둡니다.
2. 칸 번호 1~9를 입력해 빈칸에 둡니다.
3. 가로, 세로, 대각선 중 한 줄 3개를 먼저 채우면 이깁니다.
4. 9칸이 모두 찼는데 아무도 한 줄을 못 만들면 무승부입니다.
5. 한 판으로 승패를 판정합니다. 최대 9수라 1분 안에 끝납니다.

## 2. 화면 예시

```
=== 삼목 대결 (Hard) ===
컴퓨터는 절대 지지 않습니다. 비기기만 해도 성공!

 1 | 2 | 3          O |   | X
-----------        -----------
 4 | 5 | 6    →      | O |
-----------        -----------
 7 | 8 | 9            |   | X

당신의 차례 (1~9): 6
컴퓨터가 9번에 뒀습니다.
```

- 왼쪽에 칸 번호판을 항상 함께 보여줍니다. 번호를 외우지 않아도 되게 해서, 기억력이 아니라 전략만 측정하기 위해서입니다.

## 3. 난이도별 설정: AI가 달라진다

이 게임의 난이도는 숫자가 아니라 **컴퓨터의 생각 방식**이 바뀝니다.

| 난이도 | AI 클래스 | AI 전략 | 성공 조건 | 시간 보너스 기준(제안) |
| --- | --- | --- | --- | --- |
| Easy | `RandomAI` | 빈칸 중 무작위 | **승리** | 60초 |
| Normal | `BlockingAI` | 플레이어가 다음 수에 이기는 칸이 있으면 막음, 없으면 무작위 | **승리** | 60초 |
| Hard | `MinimaxAI` | 모든 경우를 끝까지 계산해 최선의 수 | **무승부 이상** | 60초 |

**Hard 성공 조건이 다른 이유**: 틱택토는 양쪽이 완벽하게 두면 항상 무승부로 끝나는 게임입니다. MinimaxAI는 완벽하게 두므로 플레이어는 이론상 이길 수 없습니다. 승리를 조건으로 두면 Hard는 클리어 불가능한 게임이 됩니다.

**Normal에서 이길 수 있는 이유**: BlockingAI는 한 수 앞만 막습니다. 플레이어가 **양쪽에서 동시에 이기는 수(포크)**를 만들면 한쪽만 막을 수 있어서 집니다.

## 4. 핵심 설계: 인터페이스 + 전략 패턴

### 왜 `AIStrategy`는 추상 클래스가 아니라 인터페이스인가

| | `MiniGame` | `AIStrategy` |
| --- | --- | --- |
| 종류 | abstract class | interface |
| 공통 코드 | 있음 (`play()` 흐름, `name`) | 없음 |
| 자식이 물려받는 것 | 코드 + 약속 | 약속(`choose()`)만 |

AI 3종은 알고리즘이 완전히 달라 **공유할 코드가 없습니다.** "판을 주면 둘 칸 번호를 돌려준다"는 약속만 같습니다. 이럴 때 인터페이스를 씁니다. 발표에서 "추상 클래스와 인터페이스를 언제 쓰는가"에 대한 근거가 됩니다.

### 뼈대

```java
// AIStrategy.java
public interface AIStrategy {
    int choose(char[] board);    // 둘 칸의 인덱스(0~8)를 반환
}
```

```java
// RandomAI.java, BlockingAI.java, MinimaxAI.java
public class RandomAI implements AIStrategy {
    @Override
    public int choose(char[] board) {
        // TODO
    }
}
```

```java
// TicTacToe.java 안에서 AI를 쓰는 방식
AIStrategy ai = /* 난이도에 맞는 AI 객체 (Map에서 조회) */;
int cell = ai.choose(board);     // 다형성: 같은 호출, 난이도마다 다른 알고리즘
```

`TicTacToe`는 지금 상대가 `RandomAI`인지 `MinimaxAI`인지 모르고 `choose()`만 부릅니다. 새 AI(예: 공격 우선 AI)를 추가해도 `TicTacToe` 코드는 바뀌지 않습니다.

## 5. AI별 구현 힌트

### RandomAI
빈칸 목록을 구해서 그중 하나를 랜덤으로 고릅니다.

### BlockingAI
1. 빈칸마다 "플레이어(`O`)가 여기 두면 이기는가?"를 확인합니다.
2. 그런 칸이 있으면 그 칸에 둡니다(막기).
3. 없으면 무작위로 둡니다.

### MinimaxAI (의사코드)

**아이디어**: "내가 여기 두면 → 상대는 나에게 가장 불리한 수를 둘 것이고 → 그러면 나는 가장 유리한 수를 둘 것이고 → …"를 게임이 끝날 때까지 끝까지 따라가서 점수를 매깁니다.

```
점수 정의: AI 승리 = +1, 플레이어 승리 = -1, 무승부 = 0

minimax(판, AI차례인가):
    판이 끝났으면 → 위 점수 반환
    AI 차례면     → 모든 빈칸에 X를 둬 보고, minimax(새 판, 플레이어 차례) 중 최댓값 반환
    플레이어 차례면 → 모든 빈칸에 O를 둬 보고, minimax(새 판, AI 차례) 중 최솟값 반환

choose(판):
    모든 빈칸에 X를 둬 보고, minimax(새 판, 플레이어 차례)가 가장 큰 칸을 반환
```

- AI는 점수를 **최대화**, 플레이어는 **최소화**한다고 가정합니다. 그래서 이름이 Mini + Max입니다.
- 재귀(자기 자신을 다시 호출)를 씁니다. 재귀가 처음이라면 "판이 끝났으면 반환"하는 종료 조건부터 먼저 작성하세요. 종료 조건이 없으면 `StackOverflowError`가 납니다.

## 6. 보조 메서드 (`BoardUtil`)

AI 3종과 `TicTacToe`가 모두 쓰는 판 관련 기능은 `BoardUtil`에 `static` 메서드로 모읍니다.

| 메서드 | 하는 일 |
| --- | --- |
| `winner(char[] board)` | `'O'`, `'X'`, 또는 승자 없음을 반환 |
| `emptyCells(char[] board)` | 빈칸 인덱스 목록 반환 |
| `place(char[] board, int cell, char mark)` | **복사본**에 수를 둔 새 판 반환 |
| `isFull(char[] board)` | 9칸이 다 찼는지 |

**승리 판정 힌트**: 이기는 줄은 8개뿐입니다(가로 3, 세로 3, 대각선 2). 8줄의 인덱스 조합을 `int[][]` 상수로 적어두고, 각 줄의 세 칸이 같은 표시인지 확인합니다.

### ⚠️ 가장 흔한 버그: 배열은 참조다

```java
char[] copy = board;          // ❌ 복사가 아님! 같은 배열을 가리킴
char[] copy = board.clone();  // ✅ 새 배열로 복사
```

Java 배열 변수는 배열 자체가 아니라 **배열의 위치(참조)**를 담습니다. `place()`에서 원본을 직접 바꾸면 Minimax가 "둬 보기"를 할 때마다 실제 판이 오염되어 AI가 엉뚱한 수를 둡니다. 반드시 `clone()`한 복사본에 둡니다.

## 7. 성능

플레이어가 먼저 두므로 AI의 첫 수 시점에 남은 칸은 8개입니다. 탐색할 경우의 수는 최대 8! ≈ 4만 개라 1초 안에 끝납니다. 별도 최적화는 필요 없습니다.

## 8. 입력 검증

| 입력 | 처리 |
| --- | --- |
| 1~9 외 숫자, 문자 | 재입력 |
| 이미 찬 칸 | 재입력 ("이미 놓인 칸입니다") |

## 9. 테스트 체크리스트

- [ ] 승리 판정이 가로 3, 세로 3, 대각선 2줄을 모두 잡아냄
- [ ] 9칸이 찼고 승자가 없으면 무승부 처리
- [ ] `place()`가 원본 판을 바꾸지 않음
- [ ] BlockingAI: 플레이어가 `O | O |  `일 때 3번 칸을 막음
- [ ] BlockingAI: 플레이어가 포크를 만들면 플레이어가 이길 수 있음
- [ ] MinimaxAI: 여러 번 대전해서 한 번도 지지 않음
- [ ] Hard: 무승부를 성공으로, Easy · Normal: 무승부를 실패로 판정
